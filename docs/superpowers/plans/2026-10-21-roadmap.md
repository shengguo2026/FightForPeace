This roadmap splits the Stage 1 vertical slice into **15 milestones** (M0–M14) and Stage 2 into **9 further milestones** (M15–M23). Each one ends with something you can run on your own machine (or, when nothing is interactive yet, browser screenshots and a short video from automated tests), plus a checklist of what to try and what feedback I need. Each milestone gets its own detailed task plan, written just before it starts, so that later plans can use what we learn earlier. The first detailed plan (M0) is `2026-10-21-m0-foundations.md`.

## How every milestone is delivered to you

1. I open a pull request on `shengguo2026/FightForPeace` with the milestone's work. CI runs type checks, lint, unit tests, deterministic replay tests and a browser test that captures screenshots.
2. I post a short message with screenshots (and a GIF/WebM for motion), a "What to test" checklist, and the commands to run it locally:
   ```
   git pull
   pnpm install
   pnpm dev        # then open http://localhost:5173
   ```
3. You test and give feedback. I fix what you report, then merge after your approval.

## Placeholder-first asset policy

- From M0 onwards, every visual, audio and video asset is requested through a **logical asset ID** (for example `hero.mountain.pose.idle.01`, `sfx.hit.light.01`, `cine.stage1.intro.shot03`).
- When no approved asset exists, the asset system generates a **placeholder**: a labelled coloured silhouette for characters, flat labelled panels for backgrounds, a tone or click for SFX, and a captioned still card for cinematics.
- When you deliver generated images or clips (all at once or partially), I ingest them into `assets/` with manifest entries, review them at gameplay scale, and the placeholder for that ID disappears automatically. No code changes are needed.
- SFX start from open-source and CC0 sources, and any sound can later be replaced (for example by ElevenLabs output) by dropping in a file with the same logical ID.

## Running locally (no hosting)

- Requirements on your Windows machine: **Node.js 24** and **pnpm** (already installed) (one-time install; exact steps are in the README from M0).
- `pnpm dev` serves the game on `http://localhost:5173`. `pnpm build && pnpm preview` serves an optimized local build.
- For LAN co-op (M12), **each computer runs the game locally** and the guest joins the host's room server with its LAN IP, port and room code (see `docs/review/03-network-play-and-licensing.md`).

## Portable build (from M4)

From M4 onwards, `pnpm release` produces `release/FightForPeace-<version>.zip` (the folder is git-ignored). Unzip it anywhere and double-click `start.bat` (Windows) or `start.sh` (Linux; `start.command` on macOS). The script checks for Node.js 24+ and, if it is missing, downloads a portable copy into the game folder once; then it starts the game's local server on port 6006, or the next free port, and opens the default browser. Nothing is installed system-wide. CI attaches the zip to milestone PRs from M9, and version tags publish it as a GitHub Release. Details: `docs/review/06-input-prompts-and-portable-build.md` §2.

## Out of scope for the slice

Everything needed before selling the game (paid service plans such as Flow Music and Cloudflare, rights and provenance checks, payment, legal and tax items) is tracked in `docs/commercial-release-checklist.md`.

After the creator is satisfied with game quality: online mode (Cloudflare Pages + Workers, WebRTC with online room codes), anti-piracy/licensing (seam: `LicenseAdapter`, always "licensed" in development), and paid-user authentication. Also out of scope for the slice (Stage 2 milestones above cover them): rollback netcode, survival proxy and host migration (M15, per D9); Stage 2 heroes (M16); mounts (M17) and advanced weapons (M18). Stage Challenge mode is now designed as **Chapter Challenge** (M42). Still out of scope for the whole plan: hosting and online play; spoken dialogue (subtitled narration only unless decided otherwise).
